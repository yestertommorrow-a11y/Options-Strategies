F1  [HIGH] Every live fetch that includes an option chain throws "symbol is not defined" (REGRESSION)
  Lines: 722-723 (atmIvFromChain), called at 1958.
  `atmIvFromChain` is declared at module scope but reads `symbol`. The only `symbol` binding is
  App's useState at 1681, which this function cannot see. The script runs as a module (strict
  mode), so it throws a ReferenceError whenever `mkt` is non-null.
  The bug appeared in optionstrat_pro_fixed.html. work/original.html line 680 has no `symbol` check.
  Repro (R1): run the real handleYahooFetch source inside a closure that owns `symbol`, like App,
    with a chain payload -> price is set to 600, then the error is caught: marketError =
    "Live fetch failed: symbol is not defined…", setIv is never called, applyStrategy is never called.
  Browser impact (from code reading): on page load, the iron condor built at the placeholder price
    of $450 (line 1977) is never rebuilt at the live price. currentPrice becomes the live SPY price,
    so the default strategy is evaluated far from its strikes. The header shows "data error".
    IV is not refreshed. Loading a new ticker does not rebuild legs, so legs from the old symbol
    are evaluated at the new symbol's spot. The same happens on every refresh that returns a chain.
  Why the tests missed it: work/priority-tests.cjs puts `symbol:'SPY'` in the vm global context
    and uses `chain:null`, so atmIvFromChain is never reached and would not fail anyway.
  Fix: pass the expected symbol in, e.g. `atmIvFromChain(mkt, price, dte, expectedSymbol)` with
    `if (!mkt || (expectedSymbol && mkt.symbol !== expectedSymbol) || !mkt.chain) return null;`,
    and call it as `atmIvFromChain(mkt, mkt.price, 30, sym)`. Add a test that runs without a
    global `symbol` and with a non-null chain.

F2  [HIGH] Refreshing the quote after loading a saved or imported strategy replaces the loaded legs
  Lines: 1954-1955, 1963-1966; loadSavedStrategy 2078-2091; importStrategy 2099-2104.
  loadSavedStrategy and import change `symbol` but never update previousSymbolRef. On the next
  fetch for the loaded symbol, `sym !== previousSymbolRef.current` is true. applyStrategy then
  runs with strategyType Custom, which builds the default single long ATM call, and history is
  cleared.
  Repro (R2): previousSymbolRef='SPY', symbol='AAPL' (state after loading a saved AAPL strategy),
    fetch 'AAPL' -> applyStrategy('Custom') is called and setHistory([]) runs.
  Browser steps: save a strategy on AAPL, switch to SPY, load the AAPL strategy, press refresh.
    The saved legs are replaced by one long call. Undo is disabled, so they cannot be recovered.
    (If F1 is still present and the chain loads, the fetch throws before the rebuild, so the bug
    only shows once F1 is fixed or the chain is missing.)
  Fix: in loadSavedStrategy, set `previousSymbolRef.current = saved.symbol`. More generally, only
    rebuild when the user explicitly fetched a different ticker. Never rebuild a Custom strategy
    silently: ask first, or push the old legs onto the undo history instead of clearing it.

F3  [HIGH] One invalid persisted strategy wipes every persisted strategy
  Lines: 1736-1755 (both persistence effects), 1744 (validation of each entry), 2067-2076 (save).
  The UI can save strategies that validateStrategyImport rejects: zero legs (Save is always
  enabled), more than 40 legs, leg IV over 500 (the builder has no maximum), DTE over 3650,
  strike, premium or quantity over 100000, or an underlying price over 100000.
  On load, `parsed.map(validateStrategyImport)` throws. The catch falls through and sets
  storageReady=true. The save effect then runs in the same commit and overwrites localStorage
  with the in-memory list, which is usually [].
  Repro (R3/R3b): the four UI-creatable cases above are rejected by the loader. Simulating both
    effects in commit order with one good and one empty stored strategy leaves localStorage as "[]".
  Browser steps: enable persistence, save one normal strategy, then save one with no legs. Reload
    and enable persistence again. Both strategies are gone.
  Fix: validate each entry on its own (try/catch per entry), keep the valid ones, and keep the
    raw string or quarantine the invalid ones instead of overwriting them. Never write until a
    load has succeeded. Also block saving anything the importer would reject: require 1-40 legs
    and apply the same bounds in updateLeg (iv <= 500, expiry <= 3650, and so on).

F4  [MEDIUM] Turning persistence on throws away strategies saved earlier in the session

F5  [MEDIUM] Switching a leg Stock -> Call/Put gives a 0-DTE, 0-IV option

B. SUSPECTED ISSUES (code review; not reproduced end to end)

S1  [MEDIUM] Strategies store relative DTE, so saved and imported strategies never age
  Lines 2073, 1096, 1389. Legs store `expiry` as days-to-expiry. A strategy saved at 30 DTE and
  loaded a week later is still modelled at 30 DTE, which overstates time value. Entry premiums
  and timestamps are then inconsistent with the time remaining.
  Fix: store an absolute expiry date (epoch) per leg and derive DTE at render time, or at least
  subtract the days elapsed since the strategy's timestamp on load and warn.

S2  [MEDIUM] CBOE timestamps are probably parsed in the wrong timezone or as Invalid Date
  Lines 653, 672, 1944, 1456, 2202, 2205. `new Date(json.timestamp)` is used for the chain
  timestamp and the per-leg quote timestamp. If CBOE still sends "YYYY-MM-DD HH:MM:SS" (Eastern
  time, no offset), Chrome reads it as the viewer's local time and Safari may return Invalid Date.
  When Yahoo has no regularMarketTime, the CBOE string is also used as the underlying quote
  timestamp (1944). NOT verified, because the CBOE endpoint returned HTML to curl.
  Fix: parse it explicitly as America/New_York, and show "Unavailable" when parsing fails.

S3  [MEDIUM] The governance text contradicts actual data flows
  FORBIDDEN_ACTIONS (line 203) says the app never sends "saved strategies, symbols or settings to
  any third-party service". But every quote fetch sends the symbol to third-party relays
  (576-581: r.jina.ai, allorigins, codetabs). The optional LLM code generator sends symbol, legs
  and model to Gemini (735-751). This is a documentation and policy defect, not a calculation
  bug, but it matters for a "governed" tool.
  Fix: reword the rule, e.g. "except the ticker sent to the listed public relays and data sent
  to the user-enabled LLM", or route requests through a first-party proxy.

S4  [LOW] The external-call counter is inaccurate
  Line 1934 adds 2 only on success and only for the newest request. It also adds 2 on 45-second
  cache hits, when no network request is made. Each fetchViaRelay call can try up to 4 relays,
  and failed or superseded attempts are never counted. The governance panel (907-910) presents
  this as "External Calls This Session".
  Fix: count inside fetchViaRelay, once per actual fetch attempt.

S5  [LOW] Undo is enabled at startup and clears every leg
  Lines 1692, 1976-1978. setLegs pushes the `rawLegs` captured in its closure. The initial
  applyStrategy pushes [], and handleYahooFetch, which uses the same mount-time closure, pushes
  [] again. Clicking "Undo leg edit" right after load therefore empties the strategy. The same
  stale-closure pattern means async setLegs calls record a history entry that may not be the
  state they replace.
  Fix: use functional updates, `setRawLegs(prev => { setHistory(h => [...h.slice(-29), prev]); return next(prev); })`,
  or keep history in a reducer. Clear history after the initial build.

S6  [LOW] Typing in the ticker field silently cancels a pending LLM price verification
  Lines 2147 and 2008. Each keystroke calls invalidateQuote(). A later "Accept & Update Price"
  just closes the modal with no message.
  Fix: show "Verification expired because the ticker changed", or invalidate only on fetch.

S7  [LOW] Expirations and DTE around the expiry day
  Line 618 uses 20:00 UTC as the expiry time, which is 3 pm ET while EST is in effect (it is
  November). Same-day expirations are dropped an hour early. Line 664 rounds DTE, so contracts
  with less than about 0.5 days left show 0 DTE. Added through addChainLeg (1915) or
  enrichment (1877), they are valued at intrinsic only while the entry premium is the mid, which
  shows an immediate modelled loss. impliedVolFromPrice also returns null for T <= 0.001 (624).
  Fix: use the exchange close in America/New_York, and keep fractional DTE for the model.

S8  [LOW] Chain enrichment mixes provenance and prices from different contracts
  Lines 1874-1880. When the snapped contract has no usable price, the leg keeps the theoretical
  price calculated for the un-snapped strike and expiry, but takes the snapped strike and expiry
  and the CBOE quoteTimestamp. The label stays 'Theoretical model' next to a CBOE time.
  Fix: reprice theoretically at the snapped strike and DTE, and only copy quoteTimestamp when a
  chain price is used.

S9  [LOW] Back-solved IV ignores the shared rate and dividend assumptions
  Lines 623-634 and 712-714 use a hard-coded r = 0.05 and no dividend yield (bsCall/bsPut without
  q). The model that later reprices these legs uses model.rate and model.dividend, so T+0 P/L is
  not zero even with unchanged inputs.
  Fix: pass model.rate and model.dividend into impliedVolFromPrice and price through
  calculateOptionPrice.

S10 [LOW] Option chain shading marks puts as in the money when they are out of the money
  Lines 1583-1585 shade the whole row when strike <= spot and set the title "In the money". That
  is true for calls but false for puts. Fix: shade each side on its own.

S11 [LOW] Mobile and keyboard access to saved-strategy actions
  Line 1650: the Export JSON and Delete buttons use `opacity-0 group-hover:opacity-100`. They are
  invisible on touch devices and when reached by keyboard focus. TooltipLabel (1364-1371) is also
  hover-only. Fix: show them always on small screens, and add `focus-within:opacity-100`.
  (Static review only; layout not checked in a browser.)

S12 [LOW] Number inputs snap while typing
  Lines 1388-1395 and 2209. Clearing a strike field immediately resets the strike to spot and
  reprices. Clearing quantity resets it to 1. Clearing a model field sets it to 0. Typing a new
  value therefore causes visible repricing and changes provenance to Manual or Theoretical.
  Fix: keep the input text as a draft string and commit it on blur or Enter when it is valid.

S13 [LOW] Smaller items
  - Line 504: the LLM price regex needs cents and ignores thousands separators, so "$1,234.56"
    is read as 234.56 and "$580" is missed. The human verification gate reduces the impact.
  - Line 1456: Duplicate uses crypto.randomUUID, which does not exist outside secure contexts
    (for example http on a LAN IP), so it would throw there. Use the existing Math.random id helper.
  - Line 2178: the header shows the retrieval time next to "Yahoo + CBOE delayed", which can be
    read as the quote time. It also says "manual/quote" when a Yahoo quote loaded without a chain.
  - Lines 704 and 695: if Yahoo returns a quote object with a null price, the CBOE price is used
    but source and timestamp still name Yahoo.
  - Line 1935: dataRelay shows whichever relay succeeded last, which may be the chain's relay,
    and also on cache hits.
  - Lines 2057-2065: Hedge goes through App's setLegs, so strategyType keeps its template name
    while a stock leg is added.
  - work/color-regression.cjs: `process.exitCode=1` only fires for files containing "fixed", so
    it never fires. run-review-checks.cjs compensates by reading the JSON.

C. MODELING LIMITATIONS (documented or deliberate; not defects)
======================================================================
L1  Round-trip costs are charged even when an option expires worthless or is cash-settled (385;
    disclosed at 2210). R8: a long call expiring worthless shows -$901.30 for a $900 premium with
    a $0.65 commission per side. Exercise and assignment fees are not modelled.
L2  Stock dividend cashflows are excluded (321; disclosed at 2210). Options use a continuous yield,
    so a covered call ignores the discrete dividend and early-exercise risk.
L3  European Black-Scholes with flat per-leg IV. The IV shift is additive in vol points. No
    American early exercise, no skew dynamics.
L4  Calendar / mixed-expiry metrics are grid estimates at the first expiry (419-425) and are
    labelled approximate (1049). Breakevens beyond the sampled range are not extended in the
    approximate case (444).
L5  Trade comparison (1100-1116) always replaces every leg IV with one absolute IV. The default
    is a fixed 20%, not tied to the current IV, and the comparison cannot use each leg's own IV.
    So A and B under "same assumptions" can differ from what the builder chart shows for B.
    This matches priority 2 (common absolute IV). Consider defaulting to the current IV and
    adding a "use each leg's IV" option.
L6  Fractional option contracts are allowed (1388, 1097: minimum 0.01).
L7  The comparison and scenario grids cover a fixed ±10% and ±20% of spot.
L8  No probability estimates are shown (2251), as required. Distribution assumptions and calendar
    behavior have NOT been validated by me either.

======================================================================
D. AREAS REVIEWED WITH NO DEFECT FOUND
======================================================================
- Dividend-adjusted Black-Scholes and Greeks (319-357): put-call parity holds. Delta and theta
  for a dividend-paying put match finite differences to about 1e-5 (R7, limited by the A&S cdf).
  Gamma and vega scaling under the e^(-qT) substitution are correct. The zero-IV, zero-spot and
  zero-strike boundaries are finite and correct, including the zero-IV ITM theta.
- Same-expiry max profit, max loss and breakevens (416-448): every strike is sampled, so narrow
  spreads and butterflies are exact. The analytic tail breakeven and Unlimited detection are
  correct for long/short stock and calls.
- Entry premiums stay fixed when rate, dividend or cost assumptions change. The model is attached
  at render time (1691), and comparisonRows overrides each leg's model and IV with the shared ones.
- The comparison is limited to the earliest expiry across both A and B (1105-1107).
- Out-of-order quote responses and invalidation by ticker typing, saved load or manual price are
  handled through requestVersion (1928, 1933, 1968, 2009, 2027, 2083).
- An LLM result is applied only after the checkbox gate, and only when the ticket and symbol
  still match (2007-2012). Accepting clears the market chain and labels the source as
  "Human-verified LLM suggestion".
- Import validation (1084-1099): the file size cap (2101), enums, numeric bounds and the symbol
  pattern are enforced. Imported premiums are relabelled "Imported / unverified". Names are
  rendered as escaped text (React).
- Scenario CSV (1131-1133): header plus 7 rows, numeric only, so there is no formula injection.
- Chart shading splits exactly at breakevens. Per-leg curves sum to the total (existing tests confirmed).
